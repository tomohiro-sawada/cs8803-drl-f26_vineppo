# Reflections.

What I currently think the results mean — written by hand, by me, to test and clarify my
own understanding of an experiment. Provisional by construction: a claim that survives
here long enough graduates to the knowledge base; one that dies gets a dated record of
why I believed it.

**Agents: read, grep, and link here — never write or edit.** This README is the one
exception, since it is the contract rather than a reflection. The rule is not about
quality: an agent-written reflection defeats the purpose even when it is correct, because
the act of writing is what tests the understanding, and agent-written summaries drift
from my mental model of the experiment over time. Agent-written deliverables belong in
[`agent-reports/`](../agent-reports/) by default, or in `experiments/<class>/<run>/findings.md`
when the output is the canonical per-run record.

## Conventions

- One file per reflection: `YYYY-MM-DD_<topic>.md`. The date in the name is the epistemic
  status — "what I thought on that day" — so no `Status:` line is needed and the
  task-note check deliberately does not cover this tree.
- Open by naming what the reflection is about, anchored backwards like everything else:
  `Reflects on experiments/llm_vs_crowd/2026-08-31_multi-model-next-tick/ at `27c92a2`.`
- Never revised in place. A changed mind is a new dated file that links the old one; the
  disagreement between the two is the record of the understanding moving.

Where this sits in the pipeline: [`agent-reports/`](../agent-reports/) (agent
deliverable) → `experiments/*/findings.md` (filed per-run record) → here (human
synthesis, cross-run, provisional) → the knowledge base (established). See
[`prose/README.md`](../README.md) for the full routing table.
